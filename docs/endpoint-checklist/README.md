# Endpoint Checklist — api-server + reality-server (BIT-247)

Authoritative, test-verified classification of **every HTTP endpoint** in both backend
servers. Generated by a deterministic, reproducible audit of `origin/dev`
(`backend/servers/api-server/src/routes/**` and `backend/servers/reality-server/src/routes/**`),
cross-referenced against the `tests/*.rs` suites. See [`_SPEC.md`](./_SPEC.md) for the
exact method and taxonomy; per-domain detail is in [`groups/`](./groups).

> Snapshot: `origin/dev` @ `76df2687a` · 2026-06-28 · 208 route source files. Updated through BIT-268 Wave 4 batch merges + BIT-257 (59 unmounted routers deleted).

- **Test-verified DONE = 34.6%.** Wave 4 batch test merges (BIT-268) drove +509 endpoints from
  partial → done across all groups. BIT-257 (PR#1863) deleted 57 unmounted ROADMAP stubs,
  reducing total from 2063 → 2006.
- **Implementation breadth = 98.3%** (`done + partial`). Only **1.7% are stubs/mock/unmounted**.

**The gap is test coverage, not implementation.** The overwhelming majority of the
codebase's tests are **authorization / cross-org IDOR / RBAC rejection** suites that
assert `401/403/404` and deliberately never reach a `2xx`. They harden the security
boundary (which is the right first priority) but they do not prove the feature works,
so they cannot promote an endpoint to `done`. The BIT-268 Wave 4 batch test campaign
added happy-path coverage across every domain, raising the headline from 9.0% → 34.6%.

## Current vs. future state

**Current state.** The API surface is broad and largely built: 1971 of 2006 endpoints
(98.3%) have real handlers. Wave 4 batch testing (BIT-268) drove 34.6% of endpoints to
proven, happy-path tested status. BIT-257 cleaned up 57 unmounted ROADMAP stubs.

**Roadmap to reach high test-verified % (priority order):**

1. **De-risk the remaining mocks (3 endpoints).** `compliance.rs` gdpr/data-exports,
   `rentals.rs` id-document/extract, and reality `agency_imports` test-connection still
   return stub/fabricated data. *High priority — correctness/compliance risk.*
2. **Faults-maintenance (259 endpoints, 8.1% tested).** Largest untested group by volume.
   238 partial handlers need happy-path integration tests.
3. **Finance (234 endpoints, 13.7% tested).** 202 partial; good implementation coverage,
   needs test investment.
4. **Governance (219 endpoints, 9.1% tested).** 199 partial; voting core got 15 new
   done in Wave 3 but the bulk remains untested.
5. **Org-property (94 endpoints, 3.2% tested).** 91 partial; no batch tests yet.
6. **Reality-server (96 endpoints, 4.2% tested).** Batch 2 tests added were authz-only;
   need success-path tests for the 91 partial handlers.
7. **Decide fate of `integrations/sync.rs` (30 stubs, Epic 61).** Either add migrations
   and mount or delete the scaffold — keeping unmounted `501` code inflates the stub count.
8. **AI/automation LLM endpoints (~26 partial).** Batch4 covered registry/sessions/equipment;
   LLM generation endpoints need tests that assert 2xx (not just "not-401").

## Caveats / method notes

- No local Rust toolchain on the audit host, so coverage is determined by **static
  cross-reference** (test files hit endpoints by URI string, e.g. `.uri("/api/v1/...")`).
  This is deterministic and reproducible but conservative: a test that exercises a path
  without a clear `2xx` assertion is treated as **not** proving the success path.
- Several test files exercise the **repository layer directly** rather than the HTTP
  endpoint (noted per group). Those do not count toward `done` for the endpoint.
- A handful of routers were **dead code** (defined but never mounted, e.g.
  `signatures::document_signature_router`) — excluded from counts and flagged in group
  notes. [BIT-257](/BIT/issues/BIT-257) **deleted** `signatures::document_signature_router`
  and its `*_for_doc` handlers (the live `*_for_document` surface is unchanged).
- Endpoint counts treat each `(method, path)` pair as one endpoint; dual-mounted
  routers (e.g. `market_pricing` at `/pricing` + `/market-pricing`) are counted once.
- **`Missing=0` caveat resolved (BIT-269).** A spec→handler diff (`scripts/diff_endpoints_v3.py`)
  surfaced 65 apparent gaps in the OpenAPI spec vs. mounted handlers. All 65 were
  confirmed to be **path/method divergences** between a stale spec snapshot and the
  settled implementation (e.g. `/votes` → `/voting`, flat `/units` → nested under
  `/buildings/{id}/units`, `PATCH` → `PUT` throughout, `/reservations` → `/bookings`).
  No operation in the spec or use-case catalog lacks a mounted handler. See
  [`_SPEC_DIFF.md`](./_SPEC_DIFF.md) for the full breakdown.
