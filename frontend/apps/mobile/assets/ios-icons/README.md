# iOS AppIcon sets — Property Management mobile

Epic 85 — Coverage 85-2: App icon generation for all required sizes.

This directory holds the iOS `AppIcon*.appiconset` asset catalogs for the
React Native Property Management app. The `Contents.json` manifests are
committed here; the binary PNG files are generated by the icon generation
script and must be committed by a maintainer (see below).

## Why here and not ios/

`ios/` is **gitignored** — the Expo managed workflow generates the full Xcode
project at `expo prebuild` / EAS Build time. Only `ios/xcconfig/` (the
committed native build-layer templates) is tracked.

For the Expo managed workflow, Expo resizes `assets/images/icon.png` (and the
badged variants) to all required iOS densities automatically. The AppIcon sets
here are kept for:

- Reference — document every required size in one place.
- Bare-workflow forks — teams that check in the native `ios/` directory can
  copy these into `ios/iosApp/Resources/Assets.xcassets/` manually.
- CI artifact archiving — build pipelines that need pre-sized PNGs.

## Contents

| Directory                        | Environment  | Badge  |
| -------------------------------- | ------------ | ------ |
| `AppIcon.appiconset/`            | production   | none   |
| `AppIcon-Dev.appiconset/`        | development  | DEV    |
| `AppIcon-Staging.appiconset/`    | staging      | STG    |

Each directory contains:
- `Contents.json` — Xcode asset catalog manifest (committed, text).
- `Icon-*.png` — sized PNGs (generated, not committed until script is run).

## Generating the PNGs

```bash
# From the repository root — requires ImageMagick
./scripts/generate-rn-app-icons.sh
```

After running, stage and commit:

```bash
git add frontend/apps/mobile/assets/ios-icons/
git commit -m "chore(mobile): add generated iOS AppIcon set PNGs"
```
