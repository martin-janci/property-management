## Issues observed
1. **[P0] Subagent workspace contamination (recurrence of issue #7).** The
   Phase 5 reviewer for PR#661 ran git ops in the dispatcher's working tree
   (/home/user/property-management) instead of a dedicated worktree, leaving a
   local commit ahead of remote; the PR#640 rebaser likely did the same. This
   directly causes push conflicts and state divergence — it is the root of
   several downstream symptoms below.
2. **[P0] Subagent race on dev pushes.** Multiple subagents pushed to dev
   concurrently, triggering rapid version-bump cycles (0.2.964→0.2.968) and
   leaving the dispatcher's Phase 6 commit empty ("nothing to commit") because
   subagents pre-empted every change. No serialization point for writes.
3. **[P1] Double-counted rebase_attempts.** Both the rebaser subagent and the
   dispatcher incremented `rebase_attempts`, landing on 2 instead of 1; fixed
   by hand. Ownership of counter mutation is ambiguous.
4. **[P1] Parallel-run conflict forced a reset + re-run.** A concurrent cycle
   pushed state (generated=12:32:35Z, 137 archived) mid-transition; we reset to
   origin/dev and recomputed. Two dispatcher instances overlapped with no lock.
5. **[P1] Phase 5.5 merger stall — systemic backlog of unmergeable approves.**
   5 approved PRs are stuck on 5 distinct blockers (ci-fail, needs-human-review
   x2, ci-unknown/0-checks, dirty). The review→merge stage is converting to
   "approved" but not to "merged" — the approved pool only grows.
6. **[P2] Compaction loses phase-decision provenance.** Resuming from a summary
   meant re-querying GitHub for every gate. Works, but is slow and risks
   divergence from pre-compaction decisions.
7. **[P2] CI-unknown/0-checks PRs (e.g. #643) are unhandled.** A PR with zero
   reported checks is neither pass nor fail; the merger has no rule and silently
   leaves it stuck.

## Recommendations
- **Hard-isolate subagents to their own worktree** (`git worktree add` under
  `.claude/worktrees/<task>`), and make the dispatcher refuse to spawn any
  subagent that would operate in the dispatcher CWD. Closes #7 root cause and
  removes the race in issue 2.
- **Serialize state writes** behind a single owner: subagents return diffs,
  only the dispatcher commits/pushes assignments + version. Eliminates the
  concurrent-push version-bump storm and the empty Phase 6 commit.
- **Single owner for counters.** Either the rebaser OR the dispatcher mutates
  `rebase_attempts`, never both; document it in the rebaser contract.
- **Run-level advisory lock.** Take a lock (e.g. a `dispatcher.lock` row/ref or
  GitHub deployment lock) at Phase 1 so two cycles can't overlap; abort fast if
  held.
- **Drain the approved-but-unmergeable pool.** Per-blocker routing in Phase 5.5:
  ci-fail → Phase 5.7 respawn; needs-human-review → explicit human-escalation
  tag + stop; dirty → auto-rebase; ci-unknown/0-checks → re-trigger CI or wait,
  don't strand.
- **Persist compaction-safe phase state** (a small per-run decisions ledger in
  management state) so a post-compaction resume reloads decisions instead of
  re-deriving them.
