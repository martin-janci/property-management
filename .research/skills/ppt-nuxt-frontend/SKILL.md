# PPT Nuxt Frontend

pnpm workspace at `frontend/`. Nuxt 3 apps + TS packages. Biome for lint /
format. Generated API clients live as separate packages.

## When to invoke

Plan area is `frontend`, or *Suggested approach* references
`frontend/apps/**` or `frontend/packages/**`.

## What it gives you

- Apps & packages map
- pnpm filter syntax
- API-client regeneration loop (couples to `ppt-typespec`)

## Inputs

- A target app or package name

## Apps and packages

`frontend/apps/`:

| App | Port | Stack | Notes |
|---|---|---|---|
| `ppt-web` | 3000 | Nuxt 3 | Property Management main web |
| `reality-web` | 3001 | Nuxt 3 | Reality Portal public site |
| `mobile` | n/a | RN / Expo | React Native — see also `ppt-mobile-native` for Kotlin app |

`frontend/packages/`:

| Package | Purpose |
|---|---|
| `api-client` | Generated client for PPT API (regenerated by `just generate-api-client`) |
| `reality-api-client` | Generated client for Reality API (`just generate-reality-api-client`) |
| `admin-ui` | Admin/super-admin UI components |
| `dev-panel` | In-app dev/debug panel |
| `screen-map` | Screen-map generation tooling |
| `shared` | Cross-app types and utils |
| `sitemap` | Sitemap generation |
| `ui-kit` | Shared component library |
| `vite-plugin-ppt-worktree` | Worktree-aware vite plugin |

## Steps

1. **Install deps** (workspace-wide):
   ```bash
   cd frontend && pnpm install
   ```
2. **Iterate on one app/package:**
   ```bash
   # dev mode (Nuxt)
   cd frontend && pnpm dev:ppt          # ppt-web on :3000
   cd frontend && pnpm dev:reality      # reality-web on :3001
   cd frontend && pnpm dev:mobile       # RN/Expo

   # build / test one package
   cd frontend && pnpm -F <pkg> build
   cd frontend && pnpm -F <pkg> test
   cd frontend && pnpm -F <pkg> typecheck
   ```
3. **Regenerate the API client** after any backend API change:
   ```bash
   just generate-api                    # both clients
   just generate-api-client             # PPT only
   just generate-reality-api-client     # Reality only
   ```
   These wrap `pnpm generate-api` / `pnpm generate-reality-api`. They consume
   the spec emitted by [`ppt-typespec`](../ppt-typespec/SKILL.md). If the
   contract changed, regenerate **typespec → API spec → client** in that order.
4. **Lint / format** before pushing:
   ```bash
   just check-frontend     # Biome lint + format check
   just fix-frontend       # auto-fix
   ```
5. **Tests:**
   ```bash
   just test-frontend                       # all
   cd frontend && pnpm -F ppt-web test      # one app
   ```

## Deterministic verification

```bash
# 1. pnpm available
pnpm --version >/dev/null && echo OK
# expected: OK

# 2. workspace resolves
cd frontend && pnpm -r exec true >/dev/null 2>&1 && echo OK
# expected: OK (works even before install — exec true is a noop)

# 3. expected apps present
for a in ppt-web reality-web mobile; do
  test -f "frontend/apps/$a/package.json" || { echo "missing app: $a"; exit 1; }
done
echo OK
# expected: OK

# 4. generated api-client package present
test -d frontend/packages/api-client && echo OK
# expected: OK
```

## Smoke check (single command)

```bash
cd frontend && pnpm -r list --depth -1 --json >/dev/null
```

> First run after a fresh clone needs `pnpm install` (downloads + builds
> native deps); the smoke check above only verifies the workspace
> resolves, not that node_modules is populated.

## After-task verification

```bash
just check-frontend && just test-frontend
```
