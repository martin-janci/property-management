## Attack surface changes since 2026-05-27

- **Auth/session**: SSO callback CSRF state-bypass closed (`fix(reality-web)`, closes #1826, PR #1987) — the guard previously skipped validation when `state` was absent even though a `savedState` nonce existed; now `savedState && state !== savedState` is required whenever a nonce was issued.
- **Crypto**: `accounting_core::crypto` module added (PR #1946) — RFC-6238 TOTP, 256-bit CSPRNG share tokens, 80-bit recovery codes, SHA-256-hashed at-rest storage, `subtle::ConstantTimeEq` comparisons; migration `00204` renames `acc_share_link.token`→`token_hash`. Companion fix (PR #2074, commit `82ba218`) replaced a panicking `.expect("OS CSPRNG failed")` with a propagated `CryptoError::RngFailed` → 500, so a transient entropy-source error no longer crashes the process.
- **Dependency supply chain**: `quick-xml` XXE/billion-laughs pin (`=0.41.0`) is now enforced via a hard `cargo-deny` ban in `backend/deny.toml` (PR #2096, commit `ef516fa`), replacing an advisory-only grep guard that "never failed the build."
- **RLS**: Regional-compliance tables (`regional_compliance_configs`, `slovak_voting_configs`, `slovak_accounting_configs`, `slovak_gdpr_configs`, `slovak_gdpr_consents`, `czech_svj_configs`) all ship `ENABLE ROW LEVEL SECURITY` + `FORCE ROW LEVEL SECURITY` in migration `00197_create_regional_compliance.sql`.
- **PII**: rental guest/booking PII reads (`id_number`, `date_of_birth`, `nationality`, `id_document_url`) are now manager-gated on the read path (`list_bookings`, `get_booking`, `get_booking_with_guests`, `get_guest`) — closing a gap where any org member (not just managers) could enumerate guest PII (closes #1766, dc1568c). Sibling gap still open in draft: PR #1797 (OCR auth + rental guest PII manager-gate, 12-day-stalled draft per this run's brief — not independently verified via `gh`, see Open questions).
- **Authz pattern**: the "JWT role-claim instead of DB membership" anti-pattern (flagged by PR #1741 per commit `6626d22`'s own description, and previously fixed at #1525) recurred in `routes/integrations/booking_channel.rs` (`get_booking_conflicts`, `push_listing_to_booking`) — a manager in org A could mutate org B's Booking.com integration; fixed with `verify_org_access` + `verify_manager_role_in_org` against the path `org_id`, with same-day regression tests (resident-with-forged-manager-claim → 403).
